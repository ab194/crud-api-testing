# CRUD API for HTTP testing

A small Python API for practicing requests in Postman, Burp Suite Repeater, curl, or another HTTP client. It uses only the Python standard library and stores items in SQLite.

## Run

Requires Python 3.9 or newer. From this directory:

```bash
python3 app.py
```

The API listens on `http://127.0.0.1:8000`. Data is saved in `items.db`. Use `python3 app.py --port 8080 --db /tmp/test-items.db` to change the port or database. `--host 0.0.0.0` allows connections from other devices; the API has no authentication, so use that only on a trusted network.

### Run with Docker Compose

```bash
docker compose up --build -d
curl http://127.0.0.1:8000/health
```

The container listens on port 8000 and Compose publishes it on localhost. SQLite data is kept in the `items_data` named volume, so it survives container recreation. Stop the API with `docker compose down`; this keeps the volume. To follow logs, run `docker compose logs -f api`.

## Endpoints

| Method | Path | Action | Success |
| --- | --- | --- | --- |
| GET | `/health` | Health check | 200 |
| GET | `/api/items` | List items | 200 |
| GET | `/api/items/{id}` | Read an item | 200 |
| POST | `/api/items` | Create an item | 201 |
| PUT | `/api/items/{id}` | Replace all editable fields | 200 |
| PATCH | `/api/items/{id}` | Update supplied fields | 200 |
| DELETE | `/api/items/{id}` | Delete an item | 204 |

Use `http://127.0.0.1:8000` as the base URL. For `POST`, `PUT`, and `PATCH`, send a JSON object with `Content-Type: application/json`. The examples use item ID `1`; replace it with the `id` returned by your create request. No authentication is required.

## Item fields

| Field | Type | In requests | Description |
| --- | --- | --- | --- |
| `id` | integer | Never | Generated by the server and used in item URLs. |
| `name` | string | Required for POST and PUT | Must contain at least one non-space character. |
| `description` | string | Optional for POST and PATCH; required for PUT | Defaults to an empty string on POST. |
| `completed` | boolean | Optional for POST and PATCH; required for PUT | Defaults to `false` on POST. |
| `created_at` | string | Never | UTC timestamp set when the item is created. |
| `updated_at` | string | Never | UTC timestamp set when the item is created or updated. |

Only send `name`, `description`, and `completed` in write requests. Unknown fields are rejected. Responses use the item shape shown in the create example below.

## Health check

`GET /health`

```bash
curl -i http://127.0.0.1:8000/health
```

Returns `200 OK` with `{"status":"ok"}`.

## Create an item

`POST /api/items`

```bash
curl -i -X POST http://127.0.0.1:8000/api/items \
  -H 'Content-Type: application/json' \
  -d '{"name":"Try the API","description":"A sample item","completed":false}'
```

Returns `201 Created`, a `Location` header such as `/api/items/1`, and the new item. Only `name` is required; the other editable fields have the defaults in the table above. Example response body:

```json
{
  "id": 1,
  "name": "Try the API",
  "description": "A sample item",
  "completed": false,
  "created_at": "2026-10-05T12:00:00+00:00",
  "updated_at": "2026-10-05T12:00:00+00:00"
}
```

Save the returned `id` for the following requests.

## List items

`GET /api/items`

```bash
curl -i http://127.0.0.1:8000/api/items
```

Returns `200 OK` with `{"items":[...]}`. Items are ordered by ascending ID. An empty database returns `{"items":[]}`.

## Get one item

`GET /api/items/{id}`

```bash
curl -i http://127.0.0.1:8000/api/items/1
```

Returns `200 OK` with the item object, or `404 Not Found` if the ID does not exist.

## Replace an item

`PUT /api/items/{id}`

```bash
curl -i -X PUT http://127.0.0.1:8000/api/items/1 \
  -H 'Content-Type: application/json' \
  -d '{"name":"Updated item","description":"New description","completed":true}'
```

Include all three editable fields. Returns `200 OK` with the updated item. Its `id` and `created_at` stay the same; `updated_at` changes. A missing item returns `404 Not Found`.

## Change selected fields

`PATCH /api/items/{id}`

```bash
curl -i -X PATCH http://127.0.0.1:8000/api/items/1 \
  -H 'Content-Type: application/json' \
  -d '{"completed":true}'
```

Include at least one editable field. Other fields keep their values. Returns `200 OK` with the updated item; a missing item returns `404 Not Found`.

## Delete an item

`DELETE /api/items/{id}`

```bash
curl -i -X DELETE http://127.0.0.1:8000/api/items/1
```

Returns `204 No Content` with an empty body. A later `GET` or `DELETE` for that ID returns `404 Not Found`.

## Errors

Errors have a JSON body such as `{"error":"Item not found"}`.

| Status | Meaning |
| --- | --- |
| `400` | JSON is malformed, the body is empty, or `Content-Length` is invalid. |
| `404` | The route or item ID does not exist. |
| `413` | The request body exceeds 1 MiB. |
| `415` | A JSON write request has the wrong `Content-Type`. |
| `422` | A field is missing, has the wrong type, is not allowed, or a PATCH body is empty. |

## Postman and Burp Suite

Import [`postman_collection.json`](postman_collection.json) into Postman. Run **Create item** first; it saves the returned ID in the collection's `itemId` variable. Then run the other requests. If you build a request manually, select the method and URL above. For writes, select **Body → raw → JSON** and paste the JSON body from the example.

In Burp Suite Repeater, set the target to `127.0.0.1:8000` and send a request such as:

```http
POST /api/items HTTP/1.1
Host: 127.0.0.1:8000
Content-Type: application/json

{"name":"Burp test","completed":false}
```

Use the returned ID in later request paths. Burp Repeater calculates `Content-Length` when it sends the request.

## Continuous integration

The [GitHub Actions workflow](.github/workflows/ci.yml) runs on pushes, pull requests, and manual starts. It runs the API tests on Python 3.9 and 3.13, validates the Postman collection JSON, builds the Docker image with Compose, waits for the container health check, and calls `/health`. The container is stopped after the check.
